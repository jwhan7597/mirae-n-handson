# 외주 리뷰의 수용·반박 기록

2026-10-07. 작성 역할인 Codex의 근거 대조 기록이다. Sonnet의 원문 3개는 보존한다. 전체 판정은 모두 반려지만, 그 판정 안의 지적도 개별적으로 확인한다.

## PR 1

| 지적 | 처리 | 근거 |
|---|---|---|
| 새 통계 API·서비스의 테스트 누락 | 수용·반려 사유 | 검토 브랜치 `UnitController.java:25`, `UnitService.java:36`에 동작이 추가됐고 patch 변경 목록은 main 소스 3개뿐이다. 기존 테스트 80개 통과로 이 새 동작을 검증했다고 볼 수 없다. |
| 단원당 count 쿼리 1회의 N+1 | 제안으로 분류 | `UnitService.java:37`·`:39`에서 반복 조회한다. 실제 지연·쿼리 한도 위반 증거는 없고 요구 성능 기준도 없다. 집계 쿼리 개선은 제안으로 남긴다. |
| 테스트 mock 추가·grade 타입 확인 | 제안 | 새 서비스 테스트 작성 때 `ItemRepository` mock이 필요하다. DTO 타입 불일치의 확정 오류는 제시되지 않았다. |

## PR 2

| 지적 | 처리 | 근거 |
|---|---|---|
| 인증정보를 코드에 두고 헤더에 사용 | 수용·치명·반려 사유 | 검토 브랜치 `GradingServerClient.java:28`·`:29`, 사용처 `:60`·`:66`. 값은 교육용 더미지만 배포 코드의 하드코딩 패턴은 실습 승인 기준을 위반한다. |
| 요청 생성 테스트만 있고 실제 호출 메서드 테스트 없음 | 수용·경고 | `GradingServerClientTest.java:13`의 1개 테스트는 객체 생성만 검증한다. `GradingServerClient.java:38`의 정상·비정상 응답·I/O 실패·인터럽트는 검증하지 않는다. 실제 외부 호출 대신 가짜 객체를 사용하도록 요청한다. |
| studentId 문자열을 JSON에 직접 연결 | 수용·경고 | `GradingServerClient.java:56`. 따옴표·역슬래시를 이스케이프하지 않아 임의 식별자를 정상 JSON 값으로 표현하지 못한다. 안전한 직렬화를 요청한다. |
| HTTP 기본 주소에 Basic 인증 전송 | 수용·경고 | `GradingServerClient.java:32`·`:60`. 운영 연결 전에 암호화된 전송을 검증할 사항이다. 실습에서 외부 서버에 실제 접속하지는 않았다. |
| 실제 비밀값 폐기·교체가 필요하다는 요청 | 실제 사고 조치로 채택하지 않음 | 교육 자료의 더미값이다. 실제 유출이 확인된 경우의 조치와 구분한다. 실습 PR에서는 하드코딩 제거를 요청하며 실제 자격증명을 회전시키지 않는다. |
| grading.internal이 실제 회사 내부 호스트인지 확인 필요 | 이번 실습의 필수 쟁점에서 제외 | 교육용 patch가 제공한 주소이며 실제 사내 주소라는 증거가 없다. 외부 배포 설정을 검토할 때 다시 확인할 항목이다. |
| IllegalStateException이 공통 핸들러에서 500 처리됨 | 반박·오기 정정 | `modern/api/src/main/java/com/example/common/GlobalExceptionHandler.java:47`·`:50`은 409 Conflict를 반환한다. 500은 `:53`부터의 일반 예외 처리다. 외부 채점 오류 매핑 개선은 호출 지점이 생기면 별도 검토한다. |

원문의 테스트 통과 표는 실행 성공으로 표시됐지만 새 동작 테스트 누락도 기록되어 있다. v1에서는 실행 성공과 테스트의 대상 동작을 함께 필수로 확인하므로 해당 기준은 **미충족**이다.

## 공통

- 당시 `docs/approval-checklist.md`와 `templates/approval-checklist.md`는 같은 v0 내용이었다. v1의 유효한 기준은 **templates 경로**다. 기존 docs 복사본을 최신 기준으로 오인하지 않는다.
- 원문에 남은 잘못된 추정은 위 대응 기록으로 정정했다. 확정 근거가 없는 지적 때문에 코드를 수정하거나 새 승인을 요구하지 않았다.
- 실제 페어·사람의 판정은 수행하지 않았다. 최종 머지 결정과 팀 기준 합의는 사용자·팀의 역할로 남긴다.
