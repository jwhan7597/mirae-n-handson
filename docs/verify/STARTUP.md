# Day 2-1 시작 점검·검증 계획

2026-10-07 · 에듀테크R&D팀(rnd) 실습 초안.

## 시작 점검

- 작업 브랜치: `day1`. 시작 시 커밋되지 않은 변경 없음.
- `git fetch upstream` 후 `git merge --no-edit upstream/main`: Already up to date.
- 기준 원본: `upstream/main` = `1bb4f2f77a0ff0111ae571461327343186195487`.
- Day 1-3 마지막 커밋: `ed83a6f6d7683f58bd345d710fce90d08056f00f`.
- 기존 문항 검색 이관 코드·40개 스냅샷·Java 테스트가 있으며, 템플릿2개와 vendor patch3개도 있다.
- Claude Code 2.1.292. 리뷰는 새 Sonnet 세션, 이슈 판정·수정은 별도 작성 역할에서 수행한다.
- 팀 저장소 초대가 없어 시작 동기화는 문서 안내대로 건너뛴다. Day 2-1의 로컬 실습에는 필요하지 않다.

## 요청 범위

문항 검색 GET 하나를 현재 동작 그대로 Java API로 이관하고 테스트·분석·회고를 기록한다.
Day 1-1/2 문서·Skill, 팀 CLAUDE.md와 사전 승인된 source-map-js 보안 잠금 수정도 비교 diff에 포함된 승인된 준비 작업이다.
범용 입력 처리를 새로 개선하거나 DB·설정·의존성을 변경하는 요청은 아니다.

## 순서와 결과물

1. v0 템플릿의 모호한 표현을 찾고 `.claude/skills/verify/SKILL.md`에 실행 절차를 만든다.
2. `/verify upstream/main...HEAD`를 새 Sonnet 세션에서 호출하여 `migration-review-1.md`를 기록한다.
3. 지적을 수용·반박·확인 필요로 나누고 수용한 치명·경고만 수정한다. 원본·기존 스냅샷은 유지한다.
4. 로컬 커밋 후 새 리뷰 세션에서 같은 범위를 검토하여 `migration-review-2.md`를 기록한다.
5. vendor patch3개를 각각 독립 검토 브랜치에 적용·커밋하고 `/verify HEAD~1..HEAD`로 판정한다. 작성 역할이 기록을 대조하고 day1로 돌아온다.
6. 실습용 승인 기준 초안을 예/아니오 항목으로 고쳐 템플릿 v1과 판정표를 로컬 커밋한다.

실제 페어·팀원과의 합의가 이루어졌다고 기록하지 않는다. 세 PR은 이 로컬 실습에서 모두 직접 검토한다.

## v0에서 구체화할 항목

| 모호한 항목 | v1 초안의 방향 |
|---|---|
| 테스트가 충분하다 | 새 public 동작·분기·경계에 대응하는 검증이 있는지 확인. 단순 접근자·생성자는 제외 |
| 심각한 문제가 없다 | 실제 비밀값, 데이터 손실, 인증 우회, 외부 입력의 SQL 구문 삽입처럼 근거가 있는 항목을 정의 |
| SQL 문자열 조립 금지 | 값 바인딩과 고정 SQL 조각·정렬 allowlist를 구분. 외부 값을 SQL 구문에 직접 삽입하면 반려 |
| 범위 밖 변경이 지나치게 많지 않다 | 요청에 포함되지 않은 동작·파일 변경은 반려. 변경 파일 안의 필요한 import 정리는 허용 |
| 팀 스타일에 적절하다 | 계층 규칙·빈 catch·임시 출력은 반려, 동작에 영향 없는 네이밍 제안은 목록으로 남김 |

초안은 기존 CLAUDE.md의 테스트·범위·컨벤션 기준에서 도출한다. 실제 사내 정책이나 팀 합의로 간주하지 않는다.
API와 공유 MariaDB/PHP는 다음 Day 2-2~4 실습을 위해 실행 상태를 유지한다.
