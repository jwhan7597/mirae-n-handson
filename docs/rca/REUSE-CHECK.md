## 실제 재사용

첫 보고서는 Codex가 단계별로 분석·집계·근거 대조하여 작성했다.
두 번째는 기억이 없는 새 `claude-sonnet-5-5` 프로세스에서 `/rca b-deploy-5xx`를 호출했다. 첫 보고서와 이전 리뷰를 읽히지 않았다. 초기 등록 목록에 rca가 있고, 마스킹 규칙 파일을 실제로 읽었다.
도구에는 카운트와 선택한 마스킹 발췌를 반환하는 보조 명령을 제공했다. 보조 프로그램은 임시 로컬 도구이며 Skill은 일반적인 좁은 읽기 명령으로도 수행하도록 작성했다. 모델 실행 증빙도 마스킹 후 저장했다.

## 발견한 빈틈과 대응

- 최초 재사용 결과의 일부 “원문 발췌”는 HTTP 버전·Java 패키지명을 생략하거나 로그 수준과 메시지를 붙인 요약이었다. 해당 근거 줄에 실제로 있는 연속 부분 문자열로 정정했다.
- 시각 차이의 근사값과 몇 초 차이를 확정한 표현을 정정했다. 13:40 배포와 11:17~11:18 사건은 약 2시간 22~23분 차이다. 서버 시계 오차를 모르는 수 초 차이는 선후 불확실로 표시한다.
- Skill에 원문 연속 발췌·표 이스케이프·시각 계산 문장을 보강했다. 이번 수정은 재사용 중 실제로 드러난 문제에 한정했다.
- 복합 통계 명령과 마지막 `git -C ... status`가 리뷰 도구 권한으로 거부됐다. 단일 통계 명령은 성공했고 최종 상태와 숫자는 Codex가 직접 다시 확인했다. 거부된 명령이 실행됐다고 계산하지 않았다.
- 최초 마스킹된 보고서와 정정 내역을 별도 증빙에 보존했다. Skill 보강 뒤 세 번째 전체 분석 호출은 하지 않았으며, 정정 후 보고서의 23개 발췌와 수치는 직접 검증했다.

## 설명 메모

전체 요청량 급증 가설은 분당 요청 수가 오히려 줄어 기각했다.
보고서 API 요청 집중과 연결 점유는 app.log:1522, 선행 경고·보고서 스택, ReportService의 트랜잭션 범위로 연결된다.
느린 조회와 서명 계산의 기여율, 다른 API의 연결 거부 원인은 자료가 부족해 확정하지 않았다.

실제 페어에게 설명하거나 사람이 승인했다고 기록하지 않았다. 위 메모는 사용자·팀에 설명할 때 쓸 요약이다.
업무 적용: 문항·학급 보고서 API 장애 회고에 이 절차를 재사용하여 증상과 원인을 구분하고, 학생 식별정보를 가린 근거를 남긴다.
