# 레거시 모듈 문서화

분석 대상과 범위: `$ARGUMENTS`

## 모듈명
- `legacy/item-bank-php` → `docs/item-bank/`
- `legacy/assignment-thymeleaf` → `docs/assignment/`
- `legacy/grade-mssql` → `docs/grade/`
- 다른 경로이면 저장할 모듈명을 먼저 확인한다. 폴더의 기술 접미사를 그대로 문서명으로 쓰지 않는다.

## 작업 범위
- 분석 대상 코드 · 스키마는 읽기만 한다. 이번 분석의 문서만 작성한다.
- `vendor/`, `node_modules/`, `.gradle/`, `build/`, `dist/`는 탐색 대상에서 제외한다.
- 외부 라이브러리는 호출부와 파일 존재까지만 기록하고 구현 본문을 읽지 않는다.
- 화면 · 함수 하나로 제한되면 해당 진입점과 직접 연결되는 함수 · DTO · 템플릿 · 스키마만 읽는다.
- 같은 파일 안의 다른 화면이나 관련 없는 함수까지 분석 범위를 넓히지 않는다.

## 절차
1. 적용되는 `CLAUDE.md`를 확인하고, 읽을 파일과 순서 · 제외 폴더 · 주의 지점을 먼저 계획으로 제시한다.
   - 승인된 범위이면 진행한다. 추가 범위가 필요하면 이유를 설명하고 먼저 확인한다.
2. 진입점과 의존 관계를 분석해 `ARCHITECTURE.md`로 저장한다.
   - 구성: 개요 5줄 이내 / 분석 범위 / 폴더 구조 / 진입점 표 / mermaid flowchart / 호출 표 / 가장 긴 함수 3개 / 미확인 목록.
   - 호출은 `A → B (A가 B를 호출)`로 적고, include · 주입 · 템플릿 렌더링과 구분한다.
   - 함수의 실제 시작·끝 라인을 확인한다. 범위 안의 함수가 3개 미만이면 있는 것만 적는다.
3. 데이터 흐름을 분석해 `ERD.md`로 저장한다.
   - 테이블 · 뷰와 주요 컬럼 / mermaid erDiagram / 관계 표 / 테이블별 읽기·쓰기 위치 / 미확인 목록.
   - FOREIGN KEY로 선언된 관계와 JOIN에서만 추정한 관계를 `선언` / `추정`으로 구분한다.
   - 뷰는 테이블과 구분하고 기반 테이블 · 실행 필터를 명시한다.
   - SELECT와 INSERT · UPDATE · DELETE 위치를 실제 함수 또는 최상위 실행 코드로 표시한다.
4. 조건문 · SQL · 입력 검증에서 업무 규칙을 추출해 `BUSINESS-RULES.md`로 저장한다.
   - 규칙별 형식: ID(`BR-01`부터) / 규칙 한 문장 / 근거 `파일:줄번호` / 실제 코드 1~3줄 인용 / 확신도(`확실` 또는 `추정`) / 비고.
   - 매직 넘버는 `값 / 위치 / 추정 의미` 표로 모은다. 미확인 사항과 검증 이력을 별도로 둔다.
5. 단계가 끝날 때마다 문서를 저장하고 다음 단계에서는 저장한 결과를 다시 읽는다.
   - 새 세션으로 진행하거나 `/clear`할 때 저장하지 않은 결과를 잃지 않도록 한다.
6. 문서의 근거를 다시 열어 경로 · 줄번호 · 인용 코드와 조건을 확인하고, 고친 항목은 검증 이력에 남긴다.
7. 마지막으로 사람이 표본 점검할 규칙 3개를 추천한다.
   - 가장 그럴듯한 규칙 / 주석 불일치 또는 매직 넘버가 있는 규칙 / 마지막 규칙을 고르고, ID · 확인할 경로 · 질문을 제시한다.

## 근거를 기록할 때
- 경로는 저장소 루트 기준이다. 모든 구조·데이터 항목과 규칙에 실제 `파일:줄번호`를 붙인다. 근거 필드에 `DC:60` 같은 약칭을 쓰지 않는다.
- 코드는 소스를 연속된 1~3줄 그대로 인용한다. 멀리 떨어진 코드를 한 덩어리로 이어 붙이거나 줄을 합치고 설명용 주석·생략 부호를 덧붙이지 않는다.
- 근거가 여러 곳이면 각각 적고, 코드로 확인하지 못한 내용은 `미확인`으로 남긴다.

## 하지 말 것
- 존재하지 않는 함수 · 테이블을 만들어 넣거나 최상위 실행 코드를 이름 있는 함수로 적지 않는다.
- 포함 관계를 함수 호출로 바꾸거나, 주입 방향과 호출 방향을 거꾸로 적지 않는다.
- 주석만으로 규칙을 확정하지 않는다. 코드가 다르면 코드 기준으로 적고 주석 불일치를 비고에 남긴다.
- 부등호 · 숫자 · 빈값 처리 · 상태 코드를 상식으로 보정하지 않는다. 실제 분기를 확인한다.
- 테이블마다 컬럼을 확인한다. 복합 키만 있는 테이블에도 공통 `id` 컬럼이 있다고 가정하지 않는다.
- 집계로 만든 뷰 컬럼의 타입을 기반 테이블에서 복사해 확정하지 않는다. 메타데이터 확인 전에는 타입 미확인으로 표시한다.
- DB의 문자열 비교를 PHP · Java 비교와 같다고 가정하지 않는다. collation 근거를 확인하거나 미확인으로 남긴다.
- 컨트롤러의 조건과 서비스의 조건을 하나로 합쳐 모든 호출 경로의 규칙이라고 단정하지 않는다.
- try 밖의 조회까지 catch가 처리한다고 쓰지 않는다. 예외를 잡는 코드의 실제 범위를 확인한다.
- 일부만 분석한 결과를 모듈 전체의 결론으로 쓰거나 관련 없는 기능의 부재를 단정하지 않는다.
