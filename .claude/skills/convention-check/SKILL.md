# 컨벤션 점검

## 대상과 근거
1. 저장소 루트의 `CLAUDE.md`에서 적용되는 규칙을 확인한다.
2. `$ARGUMENTS`에 경로가 있으면 해당 파일 또는 폴더를 점검한다.
3. 경로가 없으면 `git status --short --untracked-files=all`, `git diff --name-only`, `git diff --cached --name-only`로 대상을 모은다.
4. 아직 add하지 않은 새 파일도 읽는다. 기존 파일은 staged · unstaged diff와 주변 코드를 함께 확인한다.
5. 적용되지 않는 항목은 제외한다. 변경과 무관한 기존 문제를 이번 변경의 위반으로 단정하지 않는다.

## 점검 항목
1. API 컨트롤러가 Repository · JdbcTemplate을 직접 사용하거나 SQL을 직접 실행하는가.
2. 빈 `catch` 또는 예외를 무시하고 성공처럼 처리하는 코드가 있는가.
3. Java에 `System.out.println`, `System.err.println`, `printStackTrace()` 또는 화면에 디버깅용 `console.log`가 있는가.
4. API 응답이 record DTO 규칙을 어기거나 JPA 엔티티를 직접 노출하는가.
5. 화면 컴포넌트가 `fetch`를 직접 호출하거나 `any`, `@ts-ignore`, 사유 없는 린트 비활성화 주석을 추가했는가.
6. 의존성 · DB 스키마 · 시드 · 접속 설정 변경이 있는가. 승인 여부를 알 수 없으면 `확인 필요`로 표시한다.
7. 새 엔드포인트 · 서비스 동작에 대응하는 테스트가 있는가. 관련 테스트를 찾지 못해도 부재를 확정할 근거가 부족하면 `확인 필요`로 표시한다.

## 출력
- 먼저 판정 요약: 점검 파일 수, 확인된 위반 건수, 확인 필요 건수.
- 이어서 위반 목록 표: `파일:줄번호 / 어긴 규칙 / 수정 방향`.
- 근거 라인을 댈 수 없는 지적은 위반으로 세지 않고 `확인 필요`로 남긴다.
- 테스트 부재는 새 동작의 선언 위치와 확인한 테스트 경로를 함께 적는다.
- 적용한 규칙의 출처를 `CLAUDE.md` 조항으로 표시한다. 결과는 한국어로 작성한다.

## 작업 범위
- 코드를 직접 고치지 않는다. 보고만 한다.
- 파일 · 스냅샷 · 설정 · Git index를 변경하지 않고, 테스트 실행이나 커밋을 수행하지 않는다.
- 새 파일을 발견했다는 이유만으로 `git add`하지 않는다.
