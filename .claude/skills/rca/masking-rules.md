# RCA 마스킹 규칙

보고서 저장·공유 전에 모든 절의 발췌·표·명령 출력에 적용한다. 로그가 더미여도 같은 규칙을 쓴다.

| 유형 | 변환 |
|---|---|
| IP 주소 | 구분이 필요 없으면 앞 두 옥텟만 남겨 `10.20.x.x`. 응답 서버·연결 거부 서버를 구분해야 하면 `API-1`, `API-2`, `교사단말A` 등 역할 별칭 사용 |
| 이메일 | 아이디를 `***`, 도메인 유지: `***@example.com` |
| 학생 식별자 | 등장 순서대로 학생A·학생B…; 같은 원본은 보고서 끝까지 같은 별칭 |
| 토큰·세션 ID·API 키·Authorization 값 | `[TOKEN]`. Bearer/Basic 종류만 남겨도 실제 값은 남기지 않음 |
| 비밀번호·접속 문자열 | `[SECRET]`. 실제 비밀번호·URI를 예시나 확인 명령에 다시 넣지 않음 |

원본과 별칭의 대응은 처리 중 메모리에만 유지한다. 대응표·마스킹 전 원본을 파일/임시 폴더/실행 증빙에 남기지 않는다.
다른 서버를 하나의 마스킹 IP로 합쳐 인과 단서를 없애지 않는다. 별칭이 역할의 추측이면 그 사실을 표시한다.
문서에 포함되지 않은 유형은 0건으로 기록한다. 유형별 건수는 선택 발췌에서의 변환 수인지, 문서 전체 출현 수인지 기준을 적는다.

## 확인

1. IP·이메일·학생 식별자·Bearer 토큰 패턴을 원본에서 검사해 0건이 아닌 탐지가 있는지 먼저 확인한다. 원문 대신 건수만 출력한다.
2. 같은 패턴을 저장할 보고서에 적용해 0건인지 확인한다. 다음 패턴은 기본 예시다.

```text
([0-9]{1,3}\.){3}[0-9]{1,3}|[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[a-z]{2,}|STU-[0-9]+|Bearer [A-Za-z0-9._-]{8,}
```

3. 이 기본 패턴만으로 Basic 인증·세션 ID·키·비밀번호·접속 문자열을 모두 잡는 것은 아니다. 선택 구간의 실제 표기에 맞춰 추가 검사하고 저장된 값이 `[TOKEN]`/`[SECRET]`인지 확인한다.
4. 버전 번호처럼 IP 모양이어도 비식별 정보임이 확인된 것은 예외로 기록할 수 있다. 마스킹된 도메인·별칭을 원본 누출로 판정하지 않는다.
5. 보고서 끝에 `마스킹 적용: 유형별 건수(집계 기준)`를 남긴다. 검사 자체가 원본을 탐지하지 못하면 통과라고 주장하지 않고 패턴을 보완한다.
