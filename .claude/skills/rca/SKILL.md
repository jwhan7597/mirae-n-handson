# 장애 로그 RCA

대상: incident-logs/$ARGUMENTS/
결과: docs/rca/$ARGUMENTS.md
경로는 저장소 루트 기준이다. 실제 하위 폴더 이름 하나를 인자로 받는다. 인자가 없거나 대상이 없으면 먼저 묻는다.

## 절차

1. **수집 범위:** 내용을 통째로 읽지 말고 wc·head·tail·rg 등의 좁은 읽기로 크기·기간·시각 형식·타임존을 확인한다. 분별 오류·요청 수로 장애 시작/끝과 앞뒤 여유 구간을 정한다. 표기 없는 타임존은 epoch·같은 사건으로 대조하고 가정을 표시한다.
2. **타임라인:** 정한 구간만 KST 시간축에 합친다. 각 사건에 파일:줄번호·요약·80자 이내의 마스킹된 발췌를 붙인다. 반복은 첫 발생과 분당 건수로 묶고 스택의 중복 오류를 새 요청으로 세지 않는다. 시계 오차를 모르는 몇 초 차이는 "선후 불확실"로 표시한다.
3. **가설:** 서로 다른 계층에서 최소 2개를 낸다. 각각 지지 근거·확인 가능한 반증 조건·명령 또는 대상 파일을 적는다. 아직 단일 원인을 확정하지 않는다.
4. **검증:** 로그로 반증을 실제 시도하고 명령·결과 숫자로 유지/기각/판단 불가를 표시한다. 남은 가설을 코드·설정과 대조해 근거 줄·채택/기각 이유·확신 수준을 기록한다. 설정값은 파일에서 확인한 것만 쓴다.
5. **리포트:** 5줄 이내 요약과 1 수집 범위, 2 타임라인, 3 가설과 검증, 4 원인, 5 근거 로그 줄, 6 수정안, 7 재발 방지, 8 모니터링, 9 확인하지 못한 것을 약 150줄에 쓴다. 직접/배경 원인을 구분하고 제안 임계값이 이번 사건에서 언제 충족됐는지 계산한다.
6. **마스킹·검사:** 저장 전에 [masking-rules.md](masking-rules.md)를 읽고 적용한다. 원본에서 탐지되는 패턴으로 보고서가 0건인지 검사하고 유형별 변환 건수를 남긴다. 최소 선행 로그·첫 주요 오류·코드/설정 근거를 실제 줄과 다시 대조한다.

발췌는 실제 근거 줄의 연속된 부분 문자열이어야 한다. 패키지명·HTTP 버전 등을 생략해 다른 원문으로 만들지 않는다. 표 안의 `|`는 이스케이프하고 원문에 backtick이 있으면 이를 담을 수 있는 코드 구분자를 쓴다. 시각 차이는 직접 계산한다.

요청이 **가설 표까지만**이면 1~3절의 가설 표 뒤에서 마스킹·검사·저장을 하고 끝낸다. 코드 대조·채택/기각·4절 이후는 진행하지 않고 미실행 범위를 표시한다.
보고서 저장 권한이 거부되면 실패 사실과 마스킹된 완전한 본문을 응답으로 반환한다. 저장했다고 주장하지 않는다.

## 경계

- 로그에 없는 줄·설정·조치·원인을 만들지 않는다. 근거가 없으면 "로그로 확인 불가"라고 쓴다.
- 가장 많은 오류나 배포 직후의 발생만으로 원인을 단정하지 않는다. 상관관계와 인과를 구분한다.
- 원본 로그·소스·설정·테스트를 수정하지 않는다. 수정은 보고서의 제안으로 남긴다.
- 부하 테스트·벤치마크·실서비스 호출·서버 중단·커밋·푸시를 수행하지 않는다.
- 마스킹 대응표를 파일에 남기거나 마스킹 전 원본을 임시 폴더·증빙 로그에 복사하지 않는다.
- 원문·명령 출력은 필요한 구간만 사용하고 공유·기록 전에 마스킹한다. 검사 결과는 값 대신 건수로 보고한다.
