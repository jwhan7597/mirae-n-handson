# 검증루프

검증 대상: $ARGUMENTS
인자가 비어 있으면 `git diff upstream/main...HEAD`를 대상으로 삼는다.
경로는 모두 저장소 루트 기준이다.

## 절차

1. 요청 범위를 한 문장으로 확인한다. 주어지지 않았으면 판정하지 말고 먼저 질문한다.
2. 비교 범위의 변경 파일 목록과 diff를 읽는다. patch는 내용·요청 문장과 `git apply --stat`을 읽는다. 제목뿐 아니라 원본 patch의 커밋 메시지 본문·호환 조건도 읽어 대상 API를 확인한다.
3. 저장소 루트의 `templates/approval-checklist.md`, `templates/verification-loop.md`, `CLAUDE.md`를 읽어 항목별로 대조한다. 컨벤션은 `.claude/skills/convention-check/SKILL.md`도 참고한다.
4. 변경된 폴더의 테스트만 실행한다. 전체 출력 대신 통과·실패·건너뜀 수와 실패한 테스트 이름을 기록한다.
   - 테스트 명령과 출력 확인 명령은 나누어 실행하고 종료 코드를 확인한다. 권한이 거부되면 실행하지 않음으로 기록한다.
   - 먼저 저장소 루트의 절대 경로를 확인한다. 도구 호출 뒤 작업 디렉터리가 유지될 수 있으므로 각 테스트는 루트 기준 절대 경로로 이동해 실행한다.
   - `modern/api` 변경: 그 폴더에서 `./gradlew test`.
   - `modern/web` 변경: 그 폴더에서 `npm test`.
   - 레거시 이관 코드: `characterization`에서 `npm test`와 `TARGET_BASE_URL=http://localhost:8080 npm test`를 둘 다 실행한다.
   - 서버가 없으면 실행하지 않고 기동을 요청한다. patch를 적용하지 않는 검토에서는 테스트를 `실행하지 않음·확인 필요`로 남긴다.
5. 네 승인 기준을 판정한다. 하나라도 미충족이면 반려한다. 확인 필요인 필수 기준이 남으면 승인하지 않는다.
6. 결과를 지정한 보고서에 기록한다. 이슈가 0건이면 경고·제안까지 한 번 더 살펴본다. 수정·재리뷰가 필요하면 만든 세션으로 돌려보낸다.

## 출력

- 판정: 승인 / 반려.
- 기준별 결과 표: 테스트 통과 / 치명 이슈 0건 / 요청 범위 이탈 없음 / 컨벤션 준수.
- 이슈 목록: 심각도(치명 / 경고 / 제안) · 파일:줄번호 · 근거 · 수정 방향.
- 필수 확인 필요와 기존부터 존재한 문제는 이번 변경의 확정 이슈와 구분한다.
- 보고서 경로가 지정되면 그 파일에만 결과를 쓴다. 체크리스트 항목은 복사하지 않고 매번 위 파일에서 읽는다.
- 보고서 쓰기 권한이 거부되면 실패 사실과 완전한 보고서 본문을 응답으로 반환해 호출자가 저장하게 한다. 저장했다고 주장하거나 다른 파일에 우회해 쓰지 않는다.

## 하지 말 것

- 리뷰 세션에서 코드·설정·테스트·스냅샷을 수정하거나 patch를 적용하지 않는다.
- 근거 줄번호가 없는 지적을 확정하지 않고 `확인 필요`로 남긴다.
- 테스트를 실행하지 않고 통과했다고 쓰지 않는다. 캐시된 결과와 이번 실행을 구분한다.
- 커밋·푸시·머지를 수행하지 않는다. 비밀값을 보고서에 원문으로 복사하지 않는다.
